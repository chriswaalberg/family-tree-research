This repo is a **Claude plugin marketplace** with one plugin: `family-tree-research` (Family Tree Research). Read this before changing anything.

The plugin name `family-tree-research`, skill name `family-tree` and marketplace name `chriswaalberg` must not change once published (it would break existing installs). Slash command: `/family-tree-research:family-tree`.

## Conventions

- **Bilingual, English default.** All docs, code, comments, script messages: English. Claude talks to end users in their language; Dutch must keep working everywhere:
  - scripts accept Dutch option names and JSON keys as aliases (`--taal`, `--titel`, `--verhalen`, `--tijdgeest`, `--regios`, `--media-map`, `--levenden-verbergen`; `voornamen`, `vader`, `bron`, …);
  - certainty statuses are accepted in both languages; `make_viewer_data.py` stores the Dutch value (`zeker`, `waarschijnlijk`, `mogelijk`, `onbekend`, `fout`, `niet gecheckt`), the viewer shows the label in its language;
  - relation types `raised/adopted/foster` map to the stored Dutch `aangenomen/adoptie/pleeg`.
- **data.json field names stay Dutch** (`versie`, `personen`, `taal`, `verhaal`, `tijdgeest`, …). Don't rename them: the viewer depends on them. Explain new fields in DATA-FORMAT.md.
- Viewer language: `taal`/`lang` in data.json; anything other than `"nl"` means English.
- Scripts: Python 3.8+, **standard library only** (Pillow optional for shrinking photos). Run with `python3 -I`.
- User-facing writing style (README, SKILL tone): warm, short, plain words, no jargon.

## Workshop (live.html + live.py)

Claude Code only; never offered in Cowork (the skill says so in `references/workshop.md`). One Workshop per tree, outliving sessions: `live.py serve` starts the server itself (`serve_here`, hidden `--detached`) in its own process group (`start_new_session`, log `<sha1>.log` next to the pointers) and stays as its keeper (`keep`: SIGTERM, which the desktop app sends when it archives the session that ran `preview_start`, ends only the keeper; Ctrl+C stops the server too; the keeper ends when the server does); the server stops itself after `IDLE_STOP` (6 h) without an open page or an event (`Hub.idle`); `live.py stop` stops it. It binds the Wi-Fi too (0.0.0.0 with the tree's `?k=` key, which sets a cookie; `--local`: 127.0.0.1 only; `--lan` is the old flag, ignored; POST `/event` only from loopback), reuses a running Workshop for the same data.json (`running_for`, checked via `/ping`; exit 0), else takes the first free port (`--exact`: only that one), and writes a pointer per tree in the system temp folder (`family-tree-research-live/<sha1 of data.json>.json`: port, pid, data, root). `emit(kind, _where=…)` sends only to the Workshop whose `root` holds `FTR_TREE`, `_where` (rebuild/check pass the file) or the current folder (`workshop_for`), never elsewhere; pointers of dead pids are removed by `workshops()`. `live.py launch` writes the tree's `.claude/launch.json` entry (current live.py path, the tree's port, other entries kept). The server serves `/` = live.html, `/data.json`, `/viewer/` = index.html (+ media next to data.json or `media_dir`), `/session` and `/session/data/<n>` (the replay: every event in order plus every data.json version, zlib in memory, `MAX_VERSIONS`/`MAX_TIMELINE`; version 0 = the tree at start; `data` events carry `n`; the page's `replay()` resets to version 0 and plays them through `handle`/`dataChanged(given)` with `SPEED` scaling `wait` and `tween`, live events are ignored meanwhile and "Back to live" reloads), `/phone` (loopback only: the phone address with its key, for the QR button; the key is fixed per tree via `tree_key`, kept in `~/.config/family-tree-research/workshop-keys.json`, cookie 30 days), `/events` (SSE: `hello` with the last 80 log events and the open progress tasks, then every event; `data` when data.json changed and parses). The page (`live.html`): `/* ===== TUNING` (`CFG`: rings, timings, how many arrivals animate one by one), `layout()` (round fan like the viewer's: father left, ring g from `RI(g)` to `RO(g)`, 0.8 per ring, rings = tree depth + 1, gaps = missing parents), `render(pending)` (Fan) and `cosmosHtml`/`starLabel` (Cosmos, the default: `VIEW`; the same slots and angles as the Fan, stars at the slot centre on equal orbits `COS_R0`…`RMAX`, so every effect works in both; `wireTap` finds the nearest star within `CFG.TAP_PX`), `diffOf(old,new)` (by GEDCOM id: added/removed people, link added/removed, certainty, source/reason (`why`), name, dates, story new/edited, media, occupation; `tgCounts` for zeitgeist per place) and `dataChanged()` (phase 1 on the old fan: cracks and removals; phase 2: newcomers start `pending` and fly in, then certainty, names, dates, glyphs), `QUEUE`/`handle()` (events play in order; `progress` skips the queue), `stepsEv` (round steps from `rebuild` via `live_step()` in gedcom_tool.py; the server's `Hub.seen` drops steps it sent before; only ops data.json can't show: `STEP_SHOW`), `renderCert` (certainty bar), `resolvePerson`/`skel`/`place` (who an event is about: GEDCOM id, else a name match on consonant skeletons with years and the fan as tie-breakers; outside the fan the nearest relative with `r_*` words), `setFocus`/`drawFocus` (ring + name per `who` at the star; `live.py focus`), the layout: a header with `#menuDlg` (☰: every control), one `.stats` line, and tabs `showTab` Workers (`WORK`/`workSeen`/`renderWorkers`, one row per `who` in a fixed order (`WORK_ORDER`: Claude first, then first seen), idle after `CFG.IDLE_S`) · Changes (`CHANGES`, `chgRender`/`chgGroup`/`chgText`: the server's `tree_changes` in live.py diffs every data.json and keeps `hub.changes` plus round steps (`STEP_CHANGES`); `hello.changes` and every `data`/`steps` event's `ch`, added before the queue; `chgObserve`/`chgLight`/`hlDraw` light up the people of the items in the list's middle band; `#chgFull` = full screen) · Log (`#feed`, `humanQ` turns archive ids into "2 records · archive") · Outside the fan (`renderTray`, rejections win); beams point and stay (`beamAim` never spins without a target; only `sweep` turns a circle) and fade with their worker, `tween` (frames plus a `TICK_MS` timer, so a hidden or busy window never stops an animation or the queue; the sweep restarts the CSS animations of everything it passed in one layout read per frame), colours as CSS variables in `:root` (charcoal + clay, like the Claude desktop app; nothing animates forever when there are many gaps: `CFG.BREATHE_MAX`; the particle loop only runs while something moves), beams per `who` (`beamAim`, `findTarget`: a GEDCOM id, else first name + surname in the query), `fz()`/`UPX` (minimum text size on screen). Texts in its own small `I18N` (en/nl): `pickLang` = `?lang=` > the reader's choice (`stamboomLang` in localStorage, the viewer's key, shared because both are served from one origin) > `taal`; the EN/NL switch (`#langsw`, the same `.vsw` component as Cosmos | Fan) calls `chooseLang`.

Three states (0.9.73): the page reports whether it is in view (`/* ===== IN VIEW` in live.html: POST `/seen` with visibilityState, size and a painted frame; the event stream `events?id=` says whether it is open), `Hub.viewer_*`/`view_state` keep it (`BEAT_FRESH`, `VIEWER_TTL`), `/ping` and the `/event` answer carry `viewers`/`visible`/`pages`; `workshop_state`/`state_text` turn it into the line the hook, `status`, `note`/`focus`/`progress` and `warn_state` print. ## Releasing a new version

1. Bump the version in three places: `plugins/family-tree-research/.claude-plugin/plugin.json`, the `metadata.version` of `SKILL.md`, and `PLUGIN_VERSION` in `viewer/index.html` (shown in the viewer's footer, "Made with Family Tree Research v…"). Check that they match:
   ```
   V=$(python3 -c 'import json;print(json.load(open("plugins/family-tree-research/.claude-plugin/plugin.json"))["version"])')
   grep -q "version: \"$V\"" plugins/family-tree-research/skills/family-tree/SKILL.md && grep -q "PLUGIN_VERSION=\"$V\"" plugins/family-tree-research/skills/family-tree/viewer/index.html && echo "versions match: $V"
   ```
2. Validate: `claude plugin validate .` (marketplace) and `claude plugin validate plugins/family-tree-research/.claude-plugin/plugin.json`.
3. Commit and push to `main`. Users with "Sync automatically" on get it by themselves.
4. Optional: rebuild the standalone package: `cd plugins/family-tree-research && zip -r -X ../../family-tree-research.plugin README.md .claude-plugin skills -x "*.DS_Store" "*__pycache__*"` (don't commit the .plugin file).

## Gotchas

- `viewer/index.html` loads data with exactly `fetch("data.json").then(r=>{if(!r.ok)throw new Error("HTTP "+r.status);return r.json()})`; `standalone_viewer.py` searches for that string. Keep it in sync if you change it.
- The viewer's language default lives in two places in index.html: `let LANG="en";` and in `prepareData`: `LANG=(d.taal||d.lang)==="nl"?"nl":"en";`.
- New user-visible viewer text goes into the `I18N` table (both `nl` and `en`), not hard-coded. The EN/NL switch (`langInit`/`setLang`, marked `/* taalswitch */`) re-runs `applyTexts()` and `render()`; anything computed once at load (like `META.titel`) must be recomputed in `setLang` too.
- In the published artifact only images work as media; PDFs only work in the standalone file.
